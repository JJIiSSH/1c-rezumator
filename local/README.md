# 1с-резюматор

Локальный интерфейс для создания резюме учеников курса 1С. Генерацию можно запускать через официальные Codex CLI с подпиской ChatGPT или Claude Code с подпиской Claude. Начальный выбор: ChatGPT, Sol high. Настройки модели в задаче разработки не влияют на генератор. API-ключи удаляются из окружения генерации, поэтому расходуются лимиты выбранной подписки и приложение не переключается на API-биллинг.

## Запуск

Откройте `Запустить 1с-резюматор.command` двойным щелчком. Дождитесь строки `1с-резюматор: http://127.0.0.1:4317`. Браузер откроется после готовности сервера. Терминал должен оставаться открытым. Для остановки нажмите Ctrl+C в его окне.

Если macOS не разрешает открыть файл двойным щелчком, запустите в терминале `zsh`, пробел, затем перетащите файл `.command` в терминал и нажмите Enter.

Ссылка: http://127.0.0.1:4317

## Использование

1. Выберите сохранённую анкету или добавьте ученика.
2. Заполните данные, загрузите PDF с текстовым слоем либо вставьте текст вручную. Ссылки на Drive открывают исходный файл; содержимое по ссылке автоматически не скачивается.
3. Во вкладке «Анкета» в блоке «Конфигурации 1С» выберите вариант с версией и нажмите «Добавить». Список сгруппирован по направлениям: торговля, бухгалтерия, зарплата, ERP, холдинги, документооборот, госсектор, CRM/склад/транспорт. Включены прежние редакции и варианты КОРП/ПРОФ. Можно добавить несколько вариантов; выбранное и собственные уточнения редактируются в поле под списком. Поле необязательное. Во вкладке «Настройки» задайте желаемую должность, направление и места работы. Москва закреплена общим правилом. Если работы не заданы, модель извлекает их из PDF; отсутствующие сведения попадают в вопросы.
4. Нажмите «Сгенерировать резюме». Обычно нужно подождать; одновременно выполняется одно задание. Есть отмена. При обновлении страницы в той же вкладке приложение пытается продолжить наблюдение за заданием.
5. Отредактируйте результат, проверьте замечания и вопросы. Скопируйте текст, скачайте TXT либо нажмите «Скачать PDF». Сервис создаст файл локально и передаст его в загрузки браузера, без системного окна печати. Для печати откройте скачанный файл.

Анкеты и правки автоматически сохраняются в `local/.data/students.json`. Это рабочие персональные данные; папка исключена из Git. При смене компьютера переносите её отдельно, если нужна история. Экспорт «Сохранить анкету» выдаёт JSON отдельного ученика. Автоматического импорта JSON пока нет.

Шкала до генерации показывает заполненность шести входных параметров. После генерации модель возвращает смысловую проверку: что есть, чего не хватает, что уточнить и что не требуется для выбранной роли. Ни одна оценка не является прогнозом позиции на hh.ru.

Исходный PDF временно разбирается локально и удаляется; извлечённый текст сохраняется в анкете и отправляется выбранной модели при генерации. Локальность интерфейса не означает офлайн-работу модели: для генерации нужен интернет.

## Подключение подписки

В Mac-приложении выберите ChatGPT или Claude и нажмите кнопку входа. Откроется официальная страница выбранного сервиса; при резервном сценарии Claude покажет одноразовый код для вставки в приложение. Пароль и токены резюматор не запрашивает. Авторизации хранятся раздельно в собственных каталогах приложения.

[Авторизация Codex](https://developers.openai.com/codex/auth/) · [Авторизация Claude Code](https://code.claude.com/docs/en/authentication) · [Правила использования Claude Code в приложениях](https://code.claude.com/docs/en/legal-and-compliance)

## Устройство

- `server.mjs` — HTTP-сервер Node.js, локальное сохранение, чтение PDF, запуск и остановка `codex exec`.
- `public/` — интерфейс без сборки и установки пакетов.
- `engine.mjs` — подготовка запроса, проверка полноты и разбор ответа.
- `prompts/rules.md` — правила редактора; этот файл можно менять. Новые правила читаются при каждой генерации; перезапуск сервера не требуется.
- `export_pdf.py` — создание PDF с кириллицей, переносами строк и страниц; используется reportlab.
- `schema.json` — форма структурированного ответа модели.
- `seed.json` — пустой стартовый список. Личные анкеты не входят в репозиторий.
- `test.mjs` — проверки правил подготовки и обработки результата.

Для ChatGPT используется `codex exec --ignore-user-config --ephemeral --sandbox read-only --output-schema …`. Для Claude используется неизменённый официальный `claude -p` с `--bare`, `--restricted`, отключёнными инструментами, одноразовой сессией и той же JSON-схемой ответа. Запрос передаётся через stdin, без оболочки. API-ключи обоих сервисов удаляются из окружения дочернего процесса. Общие ограничения официальных клиентов сохраняются.

Сервер слушает только 127.0.0.1, проверяет Host/Origin и собственный токен запросов. Прямых внешних публикаций и интеграции с аккаунтом hh.ru нет.

По умолчанию используются Node.js и Python из установленного рабочего окружения, Codex из ChatGPT.app и `claude` из PATH. Для другого компьютера доступны переменные `REZUMATOR_CODEX`, `REZUMATOR_CLAUDE`, `REZUMATOR_PYTHON`, `REZUMATOR_PORT`; Python должен иметь `pdfplumber` и `reportlab`; для PDF необходим Arial (macOS), Ubuntu из рабочего окружения или DejaVu Sans (Linux). Mac-сборка уже содержит оба официальных клиента и PDF-модуль.

Проверки: `node --test test.mjs test-legend.mjs`. Запуск вручную: `node server.mjs`.

## Адаптация в 1С

По умолчанию анкета даёт предметную область и исходные кейсы, а результат формулируется для 1С. Исходный Python/backend-стек не переносится автоматически в профиль и основные навыки. Задачи по каждому работодателю и конфигурации необязательны: модель достраивает их из общего опыта и предметной области, включая подходящие редакции, стороны обмена и механизмы 1С. Предложенные технические реализации отображаются в разделе «Что изменено», а неподтверждённые детали — в проверках и вопросах. Это адаптированный черновик для проверки куратором. При смене правил старый результат не переписывается сам: запустите новую генерацию.

Формулировки опыта: краткие задачи с предметом работы (доработки, отчёты, обмены, загрузки, оптимизация). Подробности алгоритмов не обязательны. Неподходящие для 1С кейсы исключаются. Основания этих правил и примеры: `../task_patterns_1c.md`.

PDF оформляется по структуре примера hh.ru: шапка с контактами, заголовки с линиями, периоды работы слева, описание справа, навыки метками. Логотип hh.ru и чужое фото не добавляются. Экспорт использует текущий текст редактора и данные контактов ученика.

В генерации допускаются предложенные метрики для черновика. Каждая предложенная цифра перечисляется в «Что изменено», проверка «Метрики» отмечает её как требующую просмотра. Цифры из исходника отделяются от предложений модели.

### Выбор метрик

Во вкладке «Настройки», под местами работы, находится блок «Метрики». Галка «Заполнять метрики» включена по умолчанию, в том числе для старых анкет. Выберите готовый показатель или «Своя метрика» и нажмите «Добавить». Укажите число с единицей измерения либо значения до/после; при необходимости уточните работодателя или задачу.

- Галка выключена: показатели не включаются в новую генерацию, введённые строки сохраняются.
- Галка включена, список пуст: модель предлагает метрики сама.
- Есть строки с пустыми значениями: модель дополняет эти строки.
- Все строки заполнены: используются только заданные метрики без дополнительных придуманных цифр.

Старое резюме автоматически не переписывается: после изменения метрик нужна новая генерация.

## Генератор легенд

Справа переключитесь с «Резюме» на «Легенда». Основа рассказа - текущий текст редактора резюме, включая ручные правки. При желании заполните «Что раскрыть подробнее» и нажмите «Сгенерировать легенду». Используется та же подписка и выбранные в верхней панели модель и уровень рассуждения. Одновременно можно запускать только одно задание: резюме или легенду.

Под одной кнопкой два этапа: карточки кейсов, затем проверка и написание. В результате: короткое представление, рассказ на 2-3 минуты, контекст работ, 3-4 опорных кейса, 2-3 разных факапа только в тестовых средах и 8-10 вопросов по этим кейсам. Основной рассказ о себе и двух последних работах занимает примерно 10 минут; подробные кейсы раскрываются по вопросам. Кейсы строятся по STAR с личным вкладом и бизнес-результатом. В поле «Что раскрыть подробнее» можно передать вакансию, известную причину ухода и пожелания к новой работе: акценты адаптируются, опыт не дописывается ради вакансии. Два обязательных вопроса из общего набора: причина ухода и ожидания от нового места; неизвестные мотивы требуют уточнения. RPS не обязателен для 1С, подходят сеансы, документы и длительность операций. Подачу по тексту не оцениваем; план репетиции не добавляется. Карточки доступны под редактором и скачиваются JSON. Отмена работает на обоих этапах; предыдущий результат сохраняется. Факапы и другие достроенные детали перечисляются в открытом разделе «Что дополнено». Метрики соблюдают выбранный режим; при выключении раздел нагрузок остаётся качественным.

Текст редактируется и сохраняется автоматически, доступно копирование и скачивание TXT. Экспорт анкеты JSON включает резюме и легенду. При изменении резюме, анкеты или указаний легенда помечается устаревшей. Её редактирование не меняет резюме. При ошибке или отмене предыдущий результат сохраняется.

Постоянный промпт: `prompts/legend.md`; схема ответа: `legend-schema.json`. Эндпоинты: POST `/api/legend/prompt` для просмотра собранного запроса, POST `/api/legend/generate` для запуска; наблюдение/отмена через общий `/api/jobs/:id`. Поля анкеты: `legendNotes` (строка), `legend` (результат или null), `legendSignature` (подпись источников). Результат: `legend_text`, `summary`, `checks`, `questions`, `changes`; сервер добавляет модель и версию правил.

### Ручная готовность резюме

В анкете есть отдельная галка «Резюме готово». Только она устанавливает статус «Готово» слева. Пока галка выключена, срочные анкеты показывают «Требуется срочно», даже если уже есть черновик. Снятие готовности возвращает срочность. Генерация и правки не меняют эту отметку; она сохраняется на компьютере и не влияет на промпт или актуальность резюме и легенды.

### Страница ученика в Notion

Кнопка «Создать страницу в NOTION» создаёт личную страницу в подключённом пространстве Ваше пространство Notion. Переносятся только текущий текст резюме и легенда при наличии. Проверки, предложенные изменения, служебные сводки и вопросы остаются в резюматоре и не отправляются в Notion. Исходный PDF и вся анкета не отправляются. Имя страницы: «Имя ученика | Резюме 1С».

Используется существующее подключение Notion в Codex через локальный `codex app-server` и `mcpServer/tool/call`. Модель не запускается, отдельные ключи OpenAI/Notion не нужны. Транспорт stdio, рабочая сессия ephemeral; глобальные настройки пользователя не изменяются. При смене подключённого пространства экспорт останавливается до настройки ожидаемого workspaceId в notion-export.mjs.

Ссылки сохраняются отдельно в `.data/notion-exports.json` и не влияют на статус готовности или подписи генерации. После создания доступны ссылка и кнопка «Обновить страницу в NOTION». Обновление по нажатию меняет резюме, сохраняя URL и существующую легенду Notion; легенда заменяется только при явной галке. Блок проверки при обновлении не экспортируется. Правки резюме, сделанные только в Notion, будут заменены; существующая легенда сохраняется; перед записью прежняя страница сохраняется в `.data/notion-backups/`. Дочерние страницы и базы автоматически не удаляются: Notion блокирует такую замену. При ошибке обновления ссылка сохраняется и можно повторить обновление по тому же ID. Само редактирование анкеты ничего в Notion не меняет. Если после отправки запроса результат неясен, повторное создание блокируется; нужно проверить Notion и восстановить ссылку, прежде чем повторять запись.

Официальная документация протокола: https://learn.chatgpt.com/docs/app-server .

## Несколько окон и браузеров

Анкеты, галка «Резюме готово» и список учеников синхронизируются с локальным сервером каждые 2 секунды и при возвращении во вкладку. Сохранение отправляет только изменённые поля через POST `/api/state/changes`, с проверкой предыдущего значения. Чужая правка того же поля вызывает конфликт, не перезапись: текущий текст остаётся в редакторе, сообщение просит скопировать его перед обновлением страницы. Черновой ввод во время сохранения также сохраняется. Статус готовности меняет только пользователь.

После установки этой версии один раз обновите ранее открытые вкладки. Старый POST `/api/state` отклоняется с просьбой обновить страницу, чтобы старая вкладка не могла затереть весь список. GET `/api/state` остаётся доступным. Перезапуск сервера автоматически обновляет токен запросов в новых вкладках. Для изолированных проверок сервера `REZUMATOR_DATA_DIR` задаёт отдельный каталог данных, по умолчанию используется `.data` рядом с программой.

### Загрузка учеников из Google Drive
Кнопка «Загрузить из Google Drive» читает таблицу «Анкеты учеников для резюме» (gid=0) через подключение Google Drive в Codex. API-ключи и вызовы модели не нужны. Повторные нажатия во время загрузки используют текущее задание.

Новые записи сопоставляются по Telegram без учёта регистра; сохранённая отметка времени и ссылка на PDF помогают избежать дублей. Пустые поля дополняются, ранее импортированные значения обновляются только если куратор их не изменял. Непустые ручные значения сохраняются, расхождения можно подставить кнопкой в анкете. Пустые ответы таблицы не стирают данные. Изменения, время импорта и предупреждения о файлах хранятся в `driveImport`, отдельно от промптов и подписей генерации.

Ссылки на PDF сохраняются; текст доступных PDF загружается автоматически. Для сканов без доступного текстового слоя появляется предупреждение. Готовность, резюме, легенды и страницы Notion импорт не меняет. Перед сохранением создаётся резервная копия в `.data/drive-backups/`. Сохранение использует общую очередь с ручными правками и учитывает актуальное состояние после сетевого чтения.

API: POST `/api/drive/import`, GET `/api/drive/status`, с обычным локальным CSRF-токеном. Источник зафиксирован в `drive-import.mjs`.


### Выбор подписки и модели генерации
В верхней панели доступны ChatGPT/Claude, модель и уровень рассуждения. Начальное значение: ChatGPT, Sol high. Модели ChatGPT запрашиваются через Codex app-server `model/list`; Claude использует официальные стабильные алиасы Default, Sonnet, Opus и Haiku, которые Claude Code разрешает согласно тарифу пользователя. Выбор для каждого сервиса сохраняется отдельно в `.data/generation-settings.json` и синхронизируется между окнами. Текущее задание фиксирует провайдера, модель и уровень запуска; новый выбор применяется к следующим генерациям.

API: GET `/api/models?provider=openai|anthropic`, GET/POST `/api/generation-settings`. POST принимает `settings` и предыдущие значения `before`, чтобы не затереть выбор из другого окна. Обнаружение моделей ChatGPT: https://developers.openai.com/codex/app-server#models.

### Предложенные компании и проекты
Если исходных работодателей недостаточно, генератор предлагает недостающие компании, рабочие проекты и периоды по правилу двух мест работы. В итоговом тексте не используются «Начинающий разработчик 1С», Junior, «Учебный проект» и заявления об отсутствии опыта. Исходная анкета сохраняется, предложенные компании и трудовая история отмечаются в проверке и списке изменений. Старые настройки начинающего профиля нормализуются при сборке промпта.

### Желаемый стаж без указания компаний
Во вкладке «Настройки» поле «Желаемый стаж, лет» позволяет указать суммарный стаж независимо от мест работы, например 3,5 года. Поле хранится в анкете как targetExperienceYears, в запрос передаётся experience с целым количеством месяцев и готовой строкой для заголовка. Заполненное поле имеет приоритет над датами работ и прежними текстовыми указаниями о длительности: при следующей генерации периоды пересчитываются, а изменения отмечаются в проверке. Пустое поле или 0 использует стандартные 48-54 месяца. Последняя работа в новом черновике заканчивается «по настоящее время»; заголовок стажа проверяется по двум периодам. Смена стажа делает существующий результат устаревшим; исходные данные и готовность не меняются.

### Отдельный промпт
Кнопка «Копировать отдельный промпт для легенды» копирует `prompts/legend.md` без анкеты. Этот же текст доступен через `../prompt_1c_legend.md`: отправьте его вместе с резюме в обычный чат, результат будет читаемым текстом. В сервисе JSON-формат задаётся отдельными адаптерами этапов.

### Авторская легенда в Notion
При обновлении страницы существующий раздел легенды сохраняется, меняется только резюме. Чтобы заменить легенду локальным вариантом, отметьте отдельную галку «Заменить легенду в Notion» перед обновлением. Галка не служит постоянным разрешением. Без локального текста легенды её замена не выполняется.


Карты легенд: `legend-map.mjs` строит сцену из текста и публикует её по формату зашифрованных ссылок Excalidraw (AES-GCM, zlib). POST `/api/legend/maps` принимает `{studentId}`; GET возвращает статусы по ученикам текущего пространства Notion. `legend-map-export.mjs` читает реальную легенду страницы, проверяет полноту, сохраняет исходник и `.excalidraw` в `.data/legend-maps/<hash>/`, затем добавляет или заменяет отдельный блок ссылки. Резюме, легенда и готовность не изменяются. Журнал `.data/legend-maps.json` хранит ссылку сразу после публикации, чтобы повторная проверка не публиковала новый рисунок. Ссылка содержит ключ расшифровки во фрагменте; каталог данных не публиковать.


`legend-content.mjs` проверяет только новые результаты этапа review и источник карты на служебные вставки. Старые черновики остаются редактируемыми и доступны в состоянии. Ошибка готовности сохраняет прежний результат; автоматического третьего вызова модели нет. Промпт 2.5 и адаптер review задают одинаковые правила готовых ответов и технических слоёв. Карта версии 2 использует отдельные узлы для подписанных блоков, цепочки «источник -> обработка -> приёмник» и семь разделов; обновлённая версия раскладки входит в хеш карты.

Промпт 2.5 и адаптеры обоих этапов сохраняют техническую реализацию и диагностику в solution, а организацию команды в team_process. Процесс по умолчанию единый для обеих работ: Scrum, недельные спринты, планирование, ежедневная синхронизация, ревью, проверка на копии, приёмка и выпуск, итоги и ретроспектива. Явное описание работы приоритетнее шаблона. Уточнены описания существующих полей обеих JSON-схем; структура сохранённых легенд совместима. Обновление правил само по себе не переписывает сохранённые легенды и Notion; правила применяются при следующей генерации.

### Готовность и массовая генерация легенд
`legendReady` — отдельная булева отметка, по умолчанию false; исключена из inputSignature/legendSignature и входа модели. После успешной индивидуальной или массовой генерации браузер сохраняет легенду и legendReady=true одним обновлением полей. Ручная галочка доступна в анкете и на вкладке легенды; список учеников показывает её статус. Старые легенды без поля не отмечаются готовыми автоматически.

Кнопка «Сгенерировать легенды всем без галочки «Легенда готова»» выбирает учеников с result.resume_text и legendReady!==true. Общая очередь содержит kind=legend или kind=resume, восстанавливается в той же вкладке и запускает задания последовательно. Старые сохранённые очереди без kind считаются очередями резюме. Для легенд используется /api/legend/generate и legendSignature актуального снимка. Отмена останавливает текущую генерацию и оставшуюся очередь, включая запрос запуска в полёте; ошибки и отмена не заменяют прежнюю легенду. Готовность резюме не меняется. После локального сохранения новой легенды вызывается POST /api/notion/legend с studentId. Сервер использует сохранённый материал и журнал страниц: заменяет только раздел легенды по существующему pageId или создаёт недостающую страницу. Очередь дожидается экспорта; ошибка Notion отмечается отдельно и не снимает локальную готовность.

Автоматическое обновление легенды разрешено требованием пользователя. Обычное ручное обновление резюме по-прежнему сохраняет авторскую легенду, пока явно не выбрана замена. `replaceNotionLegendOnly` сохраняет ручное резюме и существующий блок карты, создаёт резервную копию и использует точечный update_content. После новой генерации карта обновляется автоматически; после ручных правок используйте отдельную кнопку обновления карты. При неопределённом создании новая страница не создаётся повторно.

После каждой успешной генерации легенды (одной или массовой) схема Excalidraw создаётся автоматически из подтверждённого текста Notion. Очередь ждёт публикации схемы и добавления ссылки. Ошибки Notion и схемы показываются отдельно; сохранённая легенда и галка «Легенда готова» остаются. Повторное создание по неизменённому тексту использует прежнюю карту, изменение текста заменяет ссылку. Для легенд, созданных раньше, используйте «Создать карту в Excalidraw» без перегенерации. Дополнительных вызовов ИИ для схемы нет.
