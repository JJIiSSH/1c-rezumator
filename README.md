# 1с-резюматор

Локальный сервис для подготовки резюме программистов 1С и подробных рассказов для собеседований. Вы загружаете прежнее резюме, добавляете сведения об ученике и выбираете настройки. Резюматор собирает запрос, запускает выбранную модель, сохраняет результат и помогает его проверить.

Интерфейс и анкеты находятся на вашем компьютере. Для генерации используется личная подписка ChatGPT через Codex CLI или Claude через Claude Code. API-ключ для этого режима не нужен; расходуются лимиты выбранной подписки. Для генерации и интеграций нужен интернет.

## Установка и первый запуск

В репозитории находятся исходники локальной версии и Mac-приложения. Готовый установщик в этот репозиторий не загружен. Ниже описан запуск локальной версии из исходников.

Нужны Git, Node.js 22 или новее, Python 3.12 и подписка выбранного сервиса с доступом к Codex или Claude Code. Для клонирования приватного репозитория нужен доступ к нему на GitHub.

### 1. Скачайте проект

В терминале выполните:

```sh
git clone https://github.com/JJIiSSH/1c-rezumator.git
cd 1c-rezumator
```

### 2. Подключите сервис генерации

Для ChatGPT установите официальный Codex CLI и выполните вход через ChatGPT:

```sh
npm install -g @openai/codex@0.154.0
codex login
```

Для Claude установите официальный Claude Code и войдите в свой аккаунт:

```sh
npm install -g @anthropic-ai/claude-code@2.1.270
claude auth login
```

Можно подключить оба сервиса. Чтобы переключаться между ними, оба клиента должны быть установлены и авторизованы. Для Google Drive и Notion понадобится также Codex с подключённым аккаунтом ChatGPT, даже если резюме генерирует Claude.

### 3. Подготовьте работу с PDF

Находясь в корне проекта, выполните:

```sh
python3 -m venv local/.venv
local/.venv/bin/python -m pip install -r local/requirements.txt
```

Это одноразовая установка библиотек для чтения и создания PDF. Установка npm-зависимостей для самого браузерного интерфейса не требуется.

### 4. Запустите резюматор

```sh
REZUMATOR_PYTHON="$PWD/local/.venv/bin/python" npm start
```

Откройте [http://127.0.0.1:4317/](http://127.0.0.1:4317/) в браузере. Терминал с сервером должен оставаться открытым. Для остановки нажмите в нём `Ctrl+C`.

При следующем запуске достаточно открыть терминал в папке проекта и повторить команду из этого шага. Новый клон начинает с пустого списка учеников.

Если установленная ChatGPT.app содержит другую версию Codex, можно явно выбрать клиент из терминала:

```sh
REZUMATOR_CODEX="$(command -v codex)" \
REZUMATOR_PYTHON="$PWD/local/.venv/bin/python" npm start
```

### Mac-приложение

Исходники оболочки Electron находятся в `desktop/`. Инструкции по сборке и запуску: [desktop/README.md](desktop/README.md). Приложение содержит клиенты генерации и PDF-модуль, предлагает вход в браузере и мастер подключения Google Drive и Notion. Его база анкет хранится отдельно от базы браузерной версии.

## Быстрый сценарий работы

1. Нажмите **«Добавить ученика»** и укажите имя и Telegram.
2. Во вкладке **«Анкета»** загрузите прежнее резюме PDF, заполните описание проекта и задач.
3. Во вкладке **«Настройки»** выберите акценты, стаж и режим метрик. При необходимости задайте компании и отдельные указания.
4. В верхней панели выберите ChatGPT или Claude, модель и уровень рассуждения.
5. Нажмите **«Сгенерировать резюме»**.
6. Прочитайте результат и блок проверки, внесите правки прямо в редакторе.
7. После своей проверки поставьте галку **«Резюме готово»** во вкладке «Анкета».
8. Скопируйте текст, скачайте TXT/PDF или отправьте текущую версию в Notion.
9. При необходимости переключитесь на **«Легенда»** и создайте рассказ для собеседования по отредактированному резюме.

## Анкета ученика

Список учеников находится слева. Выберите ученика, чтобы открыть его данные и результаты. Правки сохраняются автоматически: дождитесь сообщения **«Сохранено на компьютере»** перед закрытием страницы.

Во вкладке **«Анкета»** можно указать:

| Поле | Что туда писать |
| --- | --- |
| Имя и фамилия, Telegram | Данные для идентификации ученика. |
| Возраст, GitHub | Необязательные сведения; включение в итоговый текст задаётся в настройках. |
| Прежнее резюме | PDF с текстовым слоем или вручную вставленный текст. |
| О проекте | Сфера бизнеса, назначение системы, пользователи и объём данных. |
| Конфигурации 1С | Выберите конфигурацию с редакцией из списка и нажмите «Добавить». Можно добавить несколько вариантов и свои уточнения. |
| Что делал ученик | Задачи, использованные технологии и личный вклад. Можно описать исходный опыт на другом стеке. |
| Сложные задачи и результаты | Что было сложно, как решили задачу и какой результат получили. |

Конфигурации, заданные куратором, учитываются при генерации. Общие правила исключают ЗУП из итоговых резюме и легенд, даже если она осталась среди вариантов интерфейса или в исходном PDF.

PDF разбирается локально. Если файл представляет собой скан без текстового слоя, вставьте текст вручную: распознавание сканов в приложении не предусмотрено. При генерации исходные сведения отправляются выбранной модели.

Шкала заполненности показывает наличие входных данных. Она не предсказывает место резюме в выдаче hh.ru. Отсутствие задач по каждому работодателю не блокирует генерацию; предложенные моделью детали затем нужно проверить.

## Настройки резюме

Во вкладке **«Настройки»** доступны:

- **Желаемая должность** и **«На чём сделать акцент»**: например, торговля и склад, ERP или интеграции.
- **Желаемый стаж, лет**: можно заполнить независимо от компаний. Например, `3,5` означает 3 года 6 месяцев. Пустое поле использует стандартный диапазон 4–4,5 года. Заполненное значение задаёт целевой стаж для пересчёта периодов черновика.
- **Возраст и GitHub**: галки управляют их включением в итоговый текст.
- **Места работы**: заданные здесь сведения приоритетнее PDF. По общему правилу в резюме раскрываются два места работы.
- **Метрики**: готовые варианты и собственные показатели с числовыми значениями и контекстом.
- **Указания для генерации**: индивидуальные требования к этому резюме. Сюда удобно добавить текст вакансии, желаемые акценты или просьбу подробнее раскрыть определённую задачу.

Город закреплён общим правилом: Москва. В шапке указывается готовность к переезду и командировкам, а под должностью - специализация «Программист, разработчик». Затем идут полная занятость, полный день/гибкий график/удалённая работа и желательное время в пути не более часа. Индивидуальные указания куратора могут изменить эти предпочтения. Общие навыки совпадают по написанию, версии и падежу со строками стека в опыте работы.

В «Обо мне» добавляются краткий живой профиль, одна личная деталь и известные контакты из шапки. Увлечение берётся из исходных сведений или указаний куратора. Если модель предлагает его для черновика, оно отмечается в списке изменений и проверке; спортивные достижения не придумываются.

Языки, водительские права, разрешение на работу, профессиональные ссылки, сертификаты 1С, город работодателя и предпочтительный способ связи добавляются только при наличии в исходных данных. Если PDF содержит несколько разных контактов, проверьте, какой из них актуален.

### Как работает галка метрик

| Настройка | Результат новой генерации |
| --- | --- |
| Галка выключена | Числовые показатели исключаются. Заполненные значения сохраняются в анкете. |
| Галка включена, список пуст | Модель предлагает правдоподобные показатели для черновика. |
| Есть строки с незаполненными значениями | Модель дополняет заданные строки, ориентируясь на их смысл и контекст. |
| Все строки заполнены | Используются заданные показатели без дополнительных придуманных цифр. |

Например, можно выбрать ускорение отчёта, указать `в 3 раза` и уточнить, что речь идёт об отчёте по остаткам.

Модель может предлагать недостающие задачи, компании, периоды и метрики. Эти предложения отображаются в проверках и списке изменений. Перед использованием резюме подтвердите их: предложенная цифра сама по себе не становится подтверждённым достижением.

## Генерация, правки и готовность

В верхней панели выберите сервис, модель и уровень рассуждения. Настройки сохраняются отдельно для каждого сервиса. Если список ChatGPT устарел, нажмите кнопку обновления рядом с выбором модели. Доступность моделей зависит от выбранного аккаунта.

Нажмите **«Сгенерировать резюме»** и дождитесь окончания. Одновременно выполняется одно задание. Переключение ученика не переносит на него генерацию другого ученика. Для отмены текущего задания используйте **«Остановить»**.

После генерации:

1. Прочитайте текст резюме.
2. Проверьте замечания, вопросы и предложенные изменения.
3. Отредактируйте текст прямо в правой панели и дождитесь сохранения.
4. Поставьте **«Резюме готово»** только после своей проверки.

Статусы слева имеют разный смысл:

| Статус | Что он означает |
| --- | --- |
| Анкета ученика | Анкета есть, результата генерации ещё нет. |
| Есть черновик | Резюме создано, но не отмечено проверенным. |
| Требуется срочно | Включена срочность; проверенная готовность ещё не отмечена. |
| Готово | Пользователь поставил галку «Резюме готово». |

Наличие резюме или страницы Notion не ставит галку готовности. Срочность сохраняется до явной отметки пользователя.

Изменение анкеты, настроек или общих правил может сделать прежний результат устаревшим. Он не переписывается автоматически. Повторная генерация заменяет текущий результат ученика, поэтому сохраните важную прежнюю версию в TXT/PDF перед запуском.

### Скачать результат

В панели результата доступны копирование текста и скачивание TXT/PDF. **«Скачать PDF»** создаёт файл локально; системное окно печати для этого не требуется. Для печати откройте скачанный PDF обычным просмотрщиком.

## Легенда для собеседования

Сначала создайте и отредактируйте резюме. Затем переключитесь на **«Легенда»** в правой панели.

1. В поле **«Что раскрыть подробнее»** задайте акценты, если они нужны. Можно вставить вакансию, известную причину ухода и пожелания к новой работе; это необязательно.
2. Запустите генерацию легенды.
3. Проверьте и отредактируйте рассказ.

Легенда строится по текущему тексту резюме, включая ручные правки. Под одной кнопкой выполняются два этапа: сбор профиля и карточек, затем их проверка и написание рассказа. В результате: представление на 15-30 секунд, рассказ на 2-3 минуты, контекст работ, 3-4 опорных кейса, 2-3 факапа исключительно в тестовых средах и 8-10 вопросов по кейсам. Достроенные детали показаны отдельно в проверках и «Что дополнено». Основной рассказ о себе и двух последних работах рассчитан примерно на 10 минут: интро на 2-3 минуты и около 3 минут на каждую работу. Кейсы следуют STAR (ситуация, задача, действия, результат), раскрывают личный вклад и пользу для бизнеса. Среди 8-10 вопросов есть причина ухода и ожидания от нового места; неизвестные мотивы не выдумываются. Вакансия меняет акценты, но не добавляет опыт. Для нагрузки 1С подходят сеансы, документы, объём базы и длительность операций; RPS не обязателен. Настройки метрик имеют приоритет. Подача и уверенность по одному тексту не оцениваются; план репетиции не включён.

После успешной генерации автоматически ставится галочка **«Легенда готова»**. Она доступна в анкете и на вкладке «Легенда», а статус отображается в списке учеников слева. Галочку можно снять вручную, чтобы включить ученика в следующую массовую генерацию. Эта отметка независима от «Резюме готово»: готовность резюме по-прежнему отмечается только вручную. Ошибка или остановка не ставят галочку и сохраняют предыдущую легенду. У старых легенд без такой отметки готовность автоматически не устанавливается.

Карточки последней генерации можно раскрыть под редактором и скачать JSON. Они не меняются автоматически при ручной правке текста. Остановка доступна на обоих этапах; при отмене или ошибке прежняя легенда сохраняется.

### Использование промпта без резюматора

Откройте [prompt_1c_legend.md](prompt_1c_legend.md), скопируйте текст и отправьте вместе с резюме в ChatGPT или Claude. Можно приложить PDF или вставить текст. Анкета и другие промпты не нужны; ответ по умолчанию будет обычным текстом. В приложении тот же файл можно скопировать кнопкой **«Копировать отдельный промпт для легенды»**. Ссылка ведёт на канонический `local/prompts/legend.md`, поэтому правила не расходятся.

Резюме и легенда сохраняются отдельно. Если после создания легенды меняется резюме, проверьте согласованность рассказа и при необходимости обновите легенду.

## Массовые операции

### Сгенерировать всем без резюме

Кнопка слева **«Сгенерировать всем без резюме»** показывает число подходящих анкет. Она запускает последовательную генерацию для учеников без текста результата. Анкеты с существующим резюме пропускаются; пустые анкеты не включаются.

Кнопка **«Сгенерировать без галочки „Готово“»** запускает ту же очередь для заполненных анкет без отметки **«Резюме готово»**. Ученик с уже созданным черновиком тоже попадёт в очередь: новый результат заменит его прежний текст и проверки. Ученики с галочкой не затрагиваются. Страницы Notion этой кнопкой не обновляются; после проверки нового резюме используйте «Обновить страницу в NOTION» у нужного ученика.

Кнопка **«Сгенерировать легенды без готовности»** запускает последовательную генерацию для учеников с непустым резюме и без галочки **«Легенда готова»**. Рядом показано число подходящих учеников. Прежняя локальная легенда заменяется только после успешного завершения обоих этапов; результат и галочка сохраняются вместе. Перед запуском каждого задания отбор проверяется повторно: уже отмеченные готовыми ученики пропускаются. Новые резюме этой кнопкой не создаются; Notion автоматически не обновляется.

Во время работы появляется **«Остановить массовую генерацию»**. Она отменяет текущее задание и останавливает очередь резюме или легенд. Одновременно работает только одна очередь. Уже полученные результаты сохраняются. Не закрывайте вкладку, пока нужна работа очереди.

Если не удалось запустить генерацию из-за подключения, входа или настроек модели, очередь останавливается после первой попытки. Исправьте причину и снова нажмите нужную кнопку массовой генерации; такая ошибка не записывается всем оставшимся ученикам.

### Добавить готовые в Notion

Кнопка **«Добавить готовые в Notion»** отправляет учеников с созданным резюме, для которых ещё нет записи об экспорте. Слово «готовые» в этой кнопке означает наличие текста: галка личной проверки не является условием отбора.

Существующие страницы не дублируются. Записи с неопределённым исходом предыдущего создания пропускаются до выяснения результата. Эта кнопка создаёт недостающие страницы; правки существующей страницы отправляйте через её кнопку обновления.

## Google Drive и Google Sheets

### Подключение в Mac-приложении

В верхней панели нажмите **«Google Drive и Notion»**:

1. При необходимости войдите в ChatGPT.
2. Установите плагин Google Drive через мастер и подтвердите доступ на официальной странице подключения.
3. Вставьте адрес нужной вкладки Google-таблицы.
4. Нажмите **«Проверить и сохранить таблицу»**.

Мастер проверяет доступ и обязательные заголовки анкеты до сохранения источника.

### Настройка браузерной версии

Мастер подключения доступен в Mac-приложении. Для запуска обычного localhost-сервера подключите Google Drive к аккаунту ChatGPT, используемому Codex, и передайте ID таблицы при запуске:

```sh
export REZUMATOR_SHEET_ID="ID_ВАШЕЙ_ТАБЛИЦЫ"
REZUMATOR_PYTHON="$PWD/local/.venv/bin/python" npm start
```

ID находится между `/d/` и `/edit` в адресе таблицы. В этом режиме используется лист `gid=0`.

### Импорт учеников

Нажмите слева **«Загрузить из Google Drive»**. Таблица должна содержать заголовки исходной анкеты: Telegram, срочность, место проживания, PDF резюме, возраст, GitHub, описание проекта, задачи и сложные задачи. Формат разбирается в `local/drive-import.mjs`.

Импорт читает таблицу и доступные PDF, не изменяя источник. Он добавляет новых учеников, заполняет пустые поля и обновляет ранее импортированные значения, если вы их не меняли вручную.

Ручные расхождения остаются в анкете: можно сравнить значения и нажать **«Подставить из таблицы»**. Если у ученика уже есть резюме, новые сведения показываются в анкете для проверки. Импорт не перегенерирует резюме, не снимает готовность и не обновляет Notion автоматически.

## Notion

В Mac-приложении откройте мастер **«Google Drive и Notion»**, подключите Notion, нажмите **«Найти моё пространство»** и подтвердите **«Использовать это пространство»**.

В браузерной версии подключение должно быть доступно аккаунту Codex. ID пространства передаётся перед запуском сервера:

```sh
export REZUMATOR_NOTION_WORKSPACE_ID="UUID_ВАШЕГО_ПРОСТРАНСТВА"
REZUMATOR_PYTHON="$PWD/local/.venv/bin/python" npm start
```

Это UUID пространства, а не ID отдельной страницы.

После подготовки результата нажмите **«Создать страницу в NOTION»**. Резюматор размещает материалы в папке-странице **«Резюме учеников»**, создаёт страницу ученика и вложенную страницу резюме с датой. Экспортируются текущие резюме и легенда, если она есть. Проверки, вопросы и предложенные изменения остаются только в резюматоре.

После правок нажмите **«Обновить страницу в NOTION»**. Обновление использует сохранённый ID страницы и не создаёт дубликат. Заголовок «Резюме ДД.ММ» получает дату обновления по московскому времени. Резюме обновляется из резюматора; существующая легенда Notion сохраняется. Для её замены отметьте галку «Заменить легенду в Notion текущей легендой резюматора». Прежнее содержимое сохраняется в локальной резервной копии. Правки, сделанные только в Notion, не возвращаются в редактор автоматически.

Не удаляйте локальный журнал экспортов: он связывает учеников со страницами и помогает избежать повторного создания.

## Сохранение и перенос данных

| Режим | Где находятся данные |
| --- | --- |
| Браузерная локальная версия | `local/.data/` в папке проекта; другой каталог можно задать через `REZUMATOR_DATA_DIR`. |
| Mac-приложение | `~/Library/Application Support/1с-резюматор/`. |

Анкеты и результаты сохраняются автоматически. Обновление страницы не стирает успешно сохранённые поля. Окна браузера, подключённые к одному серверу, синхронизируются примерно каждые 2 секунды.

Для переноса браузерной базы на другой компьютер остановите сервер и отдельно скопируйте всю папку `local/.data/`, включая журналы Notion. На новом компьютере подключите собственные аккаунты. GitHub хранит исходники, но не анкеты и авторизации.

Можно работать с существующей базой без её перемещения:

```sh
REZUMATOR_DATA_DIR="/абсолютный/путь/к/вашей/.data" \
REZUMATOR_PYTHON="$PWD/local/.venv/bin/python" npm start
```

**«Сохранить анкету»** выгружает JSON отдельного ученика. Автоматического импорта такого JSON через интерфейс пока нет.

## Частые вопросы

**После клонирования нет учеников.** Это ожидаемо: репозиторий содержит пустую стартовую базу. Добавьте учеников вручную, импортируйте таблицу или отдельно подключите свою рабочую базу.

**`127.0.0.1` не открывается.** Проверьте, что сервер запущен и в терминале нет ошибки. Адрес доступен только на том компьютере, где работает сервер.

**Ошибка `Cannot find module .../server.mjs`.** Запускайте команды из корня клонированного проекта через `npm start`. Перенос одного файла запуска без папки программы не переносит сам сервер.

**Порт 4317 занят.** Возможно, резюматор уже работает. Откройте его адрес. Для отдельного экземпляра можно задать `REZUMATOR_PORT=4318`; затем открыть соответствующий порт.

**Не определяется подписка или модель.** Проверьте вход командой `codex login status` или `claude auth status`, затем обновите страницу и список моделей. Если достигнут лимит подписки, нужно дождаться его обновления.

**Не создаётся PDF.** Убедитесь, что библиотеки установлены в виртуальное окружение, а сервер запущен с `REZUMATOR_PYTHON`, указывающим на его Python.

**Изменения не появились в Notion.** Локальное редактирование само по себе ничего туда не отправляет. Нажмите «Обновить страницу в NOTION».

**Резюме есть, но галка готовности не стоит.** Галка означает вашу проверку, поэтому её нужно поставить вручную.

## Для разработки

Структура проекта:

- `local/`: HTTP-сервер, интерфейс, интеграции, схемы ответа и тесты.
- `local/prompts/rules.md`: единый источник правил генерации резюме.
- `local/prompts/legend.md`: самостоятельный промпт и общие правила двух этапов легенды.
- `prompt_1c_legend.md`: ссылка на тот же промпт для использования с одним резюме вне приложения.
- `desktop/`: оболочка Electron, ресурсы и сценарии сборки Mac-приложения.
- `prompt_1c_instruction.md`: символическая ссылка на основные правила.
- `prompt_1c_task.md`, `candidate_input.example.json`: описание задания и пример входных данных.

Вкладка **«Промпт»** позволяет посмотреть подготовленный запрос. Общие правила меняйте в канонических файлах `local/prompts/`: сервис читает их при каждой генерации. Изменение файла правил не переписывает уже созданные результаты.

Запуск тестов:

```sh
npm test
```

HTTP-тесты используют временные базы и не меняют рабочие анкеты. Подробности реализации: [local/README.md](local/README.md). Сборка Mac-приложения: [desktop/README.md](desktop/README.md).

### Хронология резюме

Пустое поле желаемого стажа или `0` включает стандартные 4-4,5 года. Ненулевой заданный стаж имеет приоритет. Последнее место работы в новом черновике заканчивается «по настоящее время», предыдущее - конкретным месяцем. Перед сохранением проверяются оба периода и их сумма; заголовок опыта вычисляется по датам. Предложенное продление исходной работы отмечается в проверках, исходные сведения остаются в анкете.

### Оформление легенды

Легенда открывается в оформленном просмотре с навигацией, заголовками и короткими абзацами. Кнопка «Редактировать текст» открывает исходный текст; «Готово, показать оформление» возвращает просмотр. Старые легенды тоже оформляются без перегенерации. Новые легенды используют Markdown по самостоятельному промпту `prompt_1c_legend.md`.

При экспорте в Notion оформление преобразуется в заголовки, списки, выделения и блоки. Существующая легенда Notion сохраняется по умолчанию; для её замены текущей локальной легендой явно отметьте соответствующую галку перед обновлением страницы.


Карта легенды в Excalidraw

Создайте страницу ученика в Notion с легендой, затем нажмите **«Создать карту в Excalidraw»** в блоке экспорта. Карта содержит рассказ о себе, места работы, кейсы, факапы в тесте и вопросы. На странице Notion появится **«Открыть карту легенды»**: ученик открывает её в браузере, без скачивания файла.

Источник карты — актуальная легенда Notion, включая ваши ручные правки. Новая генерация ИИ не запускается. После изменения легенды нажмите **«Обновить карту в Excalidraw»**: новая ссылка заменит прежнюю. Без изменения текста повторный клик проверяет ту же карту. Ссылка даёт доступ к рисунку каждому, кому вы её передадите.


Легенда 2.5: готовый материал содержит рассказ, архитектуру проектов, объяснение выбора инструментов, 3-4 кейса, 2-3 тестовых факапа и вопросы с ответами. Неизвестные личные мотивы раскрываются несколькими готовыми вариантами без придуманной биографии. Предложенные технические детали и вопросы проверки видны куратору отдельно; в Notion и карту служебные оговорки не попадают. Карта содержит небольшие подписанные узлы и цепочки данных. Она передаёт устройство проектов и логику решений; полный разговорный текст остаётся в Notion.

В технических кейсах легенда раскрывает, что разработчик реализовал в 1С, как разобрался со сложностью, что изменил и как проверил решение. Рассказ о работодателе отдельно объясняет роли команды, планирование, спринты или другой ритм, ревью, тестирование и выпуск. По умолчанию для обоих мест работы используется единый Scrum с недельными спринтами, планированием, ежедневными синхронизациями, ревью, проверкой на копии, приёмкой и согласованным выпуском, итогами и ретроспективой. Явно заданный процесс конкретной работы имеет приоритет; использование предложенного шаблона отмечается в служебных проверках.
