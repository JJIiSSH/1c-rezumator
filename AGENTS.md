# 1с-резюматор: поддержка правил генерации

- Mac-приложение: `desktop/`, Electron + локальный сервис из `local/`. Подготовка сборки только по allowlist в `desktop/scripts/prepare-service.mjs`; `seed.json` в сборке всегда пустой, личные `.data`, PDF, токены, ID таблицы/Notion и абсолютные пути разработчика не поставлять. Канонические промпты остаются в `local/prompts`; проверять их точное совпадение со сборкой. Данные приложения и Codex-авторизация хранятся отдельно в Application Support; текущую браузерную базу не мигрировать автоматически. Для испытаний использовать `REZUMATOR_SMOKE_DIR` во временном каталоге. Первая сборка arm64 без Apple Developer подписи; не объявлять её подписанной или проверенной на Intel. Генерацию в чужом аккаунте и подключения плагинов считать проверенными только после фактической проверки, не подменять её тестом login/start.

- Модель и уровень рассуждения выбираются в верхней панели и сохраняются в `.data/generation-settings.json`. Начальное значение Sol high. Список и поддерживаемые уровни получать через Codex app-server model/list; сервер валидирует пару и фиксирует её при запуске каждого задания (резюме/легенды), записывает фактическую пару в результат. Смена во время генерации влияет только на следующие задания. Не наследовать модель задачи разработки и не менять глобальные настройки Codex.
- PDF повторяет структуру образца hh.ru: шапка с контактами, серые заголовки с линиями, даты слева и описание справа, навыки метками. Не переносить фото и личные данные из чужого образца.
- PDF создаётся локально через /api/export/pdf и export_pdf.py. Не возвращать window.print() как единственный способ получить PDF: во встроенном браузере окно печати не открывалось.
- Рабочая версия локальная: `local/`. Не публиковать без отдельного запроса пользователя.
- Основной сохранённый промпт: `local/prompts/rules.md`. Согласованные пользователем общие требования к резюме вносить в него, а не только в разовый запрос или индивидуальные notes ученика.
- `prompt_1c_instruction.md` — символическая ссылка на этот файл. Сохранять единый источник, не заменять ссылку отдельной устаревающей копией.
- При изменении структуры входа/выхода согласовывать `local/engine.mjs`, `local/schema.json`, `prompt_1c_task.md` и `candidate_input.example.json`.
- Сервис читает правила при каждой генерации; для правки текста промпта перезапуск сервера не нужен. Метка rules_version фиксирует реально использованные правила.
- Текущий режим: адаптация кейсов анкеты в профиль 1С; Москва; заданные куратором конфигурации, компании, роли и даты приоритетнее PDF; Python/Java/backend не становятся основным стеком по инерции. Технические переносы должны быть осмысленными и отражаться в changes/checks.
- Отсутствие задач по каждому работодателю и конфигураций не блокирует генерацию. Модель сама достраивает задачи, конфигурации/редакции, пары интеграций и подходящие механизмы 1С из общего контекста; предложения отражает в changes/checks, без требования вручную заполнить каждый опыт. Версия 3.12 разрешает предлагать недостающие компании и проекты с пометкой в changes/checks; сертификаты не придумывать. Корректировка дат черновика разрешена правилом целевого стажа 3.9, исходные даты сохранять. Куратор разрешил предлагать правдоподобные метрики для черновика: каждую помечать в changes, проверку метрик отмечать clarify.
- В итоговом резюме раскрывать два места работы по разделу «Два места работы» постоянного промпта: выбранная куратором пара, иначе два последних. Полную исходную историю сохранять; при нехватке работодателей предлагать недостающие компании, проекты и периоды с пометкой в changes/checks; не делить одну работу на две. Метрики исключённой работы не переносить под другого работодателя.
- Поля метрик: fillMetrics и metrics[{label,value,context}]. Выключенная галка исключает показатели из новой генерации; пустой список при включённой включает автоподбор; частично заполненный дополняется только по заданным строкам; полный список имеет приоритет без новых придуманных цифр. Сохранять значения при выключении.
- Каталог паттернов куратора в постоянном промпте: адаптировать смысл под проект, не копировать предложения и цифры дословно. Для торговли приоритетно рассматривать обмены с маркетплейсами (заказы, остатки, статусы). REST API, Диадок, RabbitMQ, контроль дублей и рефакторинг модулей допустимы при уместном контексте. Нечисловые задачи не зависят от галки метрик; не добавлять цифры ко всем задачам и не обходить режим provided/complete ради примеров.
- Структура каждой работы: компания, роль, даты; краткий контекст; задачи и результаты; строка «Стек: …» без минимального количества технологий. Общий блок навыков сохраняется.
- Москва остаётся фиксированной; гражданство, телефон и почту брать только из данных кандидата в анкете/прежнем резюме, с приоритетом явных значений куратора. Не выводить гражданство из Москвы.
- Стиль резюме: примерно 50/50 кратких и развёрнутых пунктов внутри каждой работы. Развёрнутые раскрывают механизм, контекст/цель и результат; соотношение не относится к количеству числовых метрик и не отменяет галку или заданные значения. Не требовать механизм реализации в каждом пункте, не добавлять устройство регистров/очередей, запросы в цикле и объяснения про UDP/внешние шлюзы. Нерелевантный исходный кейс можно исключить вместо обязательного переноса.
- В задачах называть процесс/функциональность: оформление заказов, расчёт цен и скидок, резервирование товаров, складские операции. Избегать пустых сочетаний «доработка заказов/цен/остатков». Не превращать уточнение процесса в описание алгоритма.
- В тексте резюме использовать обычный дефис вместо длинных/средних тире; не добавлять декоративные маркеры, эмодзи и стрелки. Нормализация результата находится в normalizeResumeText в local/engine.mjs.
- Сохранять данные учеников в local/.data; не заменять их тестовыми анкетами. Перед перезапуском проверять отсутствие активной генерации.
- Новые требования пользователя важнее предыдущих редакторских предположений. Не возвращать отменённые правила при последующих правках.
- Должности каждого раскрытого места работы тоже адаптировать в профиль 1С, по умолчанию «Программист 1С». Не сохранять Golang/Java/backend и нерелевантные роли из PDF над задачами 1С. Явная должность куратора приоритетнее; не повышать уровень автоматически. Замены отражать в changes/checks, исходные компании, даты и текст PDF сохранять. Правило введено в версии 3.6.

- Генератор легенд: отдельный prompts/legend.md и legend-schema.json; Выбранные в верхней панели модель и уровень рассуждения через ту же подписку. Основой является текущий result.resume_text, включая ручные правки. Не переносить ограничения краткости/50-50 из резюме в подробный рассказ. Сохранять компании, даты, стек и метрики; достроенные проекты, команды и факапы отмечать в changes/checks.
- Легенда хранится в student.legend отдельно от result; legendNotes задаёт акценты, legendSignature отслеживает изменения источников. Легенда и её заметки не должны менять подпись входных данных резюме. Анкета и обе версии результатов сохраняются вместе.
- Структура легенды: рассказ о себе по лекции; два работодателя из резюме; контекст/команда/процессы; конкретный проект и путь данных; личный вклад; нагрузки; задачи для гордости; факап и выводы; стек; вопросы для подготовки. Не придумывать публичные выступления и наставничество. Образование брать из текущего резюме с сохранением пометок о предложенной замене, не достраивать историю учёбы. При выключенных метриках нагрузки раскрывать без чисел.

- Образование: по прямому запросу куратора допускается предложенная замена вуза/направления на узнаваемый технический вариант для черновика, включая нетехническое образование или отсутствие высшего. Курсы не считать высшим образованием. Исходные сведения сохранять; каждую замену помечать в changes/checks (clarify). Не выдумывать дипломы, номера, научные степени, даты и историю учёбы. Подробности в разделе «Образование» канонического промпта.

- Kafka исключена по прямому запросу куратора из резюме и легенд: не переносить её из исходного PDF; адаптировать обмены через уместные HTTP-сервисы/REST API, не подставлять другой брокер автоматически.
- Готовность: resumeReady=false по умолчанию; меняется только явной галкой пользователя. Генерация, редактирование и наличие result не снимают urgent и не устанавливают готовность. Слева приоритет: Готово, затем Требуется срочно, затем Есть черновик/Анкета ученика. resumeReady исключён из подписей генерации и не передаётся модели.

- Экспорт в Notion: отдельный NotionClient через codex app-server, без model turn и API-ключей. Использовать только проверенное подключение workspace из notion-export.mjs; пользователь нажатием кнопки разрешает создание одной личной страницы текущего ученика. Переносить только текущие result.resume_text/legend.legend_text; summary/checks/changes/questions оставлять в резюматоре; не отправлять весь PDF/анкету. Дедупликация и журнал `.data/notion-exports.json` отдельно от students.json. При неопределённом исходе записи не повторять создание автоматически. Экспорт не устанавливает resumeReady. Ссылки сохранять; проверки происхождения данных сохранять локально, не экспортировать в Notion.

- Версия 3.8: в каждом резюме минимум одна распространённая конфигурация (БП, УТ, ERP, КА, УНФ, Розница, Документооборот) с задачей и стеком той же работы. Редакция по периоду. Самописные/отраслевые решения допустимы дополнительно; предложения помечать в changes/checks. ЗУП исключена из резюме и легенд, включая старые настройки и PDF; исходники не стирать. Легенда сохраняет выбранную конфигурацию текущего резюме.

- Обновление Notion: явная кнопка заменяет содержимое уже созданной страницы по сохранённому pageId, без создания дублей. Перед заменой fetch и локальная копия в `.data/notion-backups/`; после записи проверочный fetch. Не включать allow_deleting_content. При сбое сохранять URL, pageId и последний успешный contentHash; готовность ученика не менять.

- Версия 3.9: целевой суммарный стаж 48-54 месяца на два места, обычно 51 месяц. Для существующих работодателей разрешено предлагать корректировку периодов черновика; оригинальные даты/PDF сохранять, изменения перечислять в changes и checks (clarify). Явно заданные куратором периоды приоритетнее диапазона: конфликт отметить. По версии 3.12 при отсутствии работодателей разрешено предложить рабочий сценарий, компании и периоды; факт отсутствия подтверждения хранить в changes/checks. Сумма месяцев включительно должна совпадать с заголовком, без двойного счёта. Легенда сохраняет новую хронологию текущего резюме.

- Синхронизация вкладок: GET `/api/state` для чтения, POST `/api/state/changes` для сохранения изменений полей с before/value. Старый POST всего массива запрещён (409), в том числе для вспомогательных скриптов: использовать studentChanges из state-sync.mjs. Конфликт одного поля не перезаписывает серверные данные. Фоновое чтение не должно терять локальный ввод или ответ более нового сохранения. Не тестировать изменения готовности на реальных учениках: HTTP-тесты используют временный REZUMATOR_DATA_DIR.

- Версия 3.10: явно названные конфигурации 1С из всей анкеты и PDF обязательно использовать в соответствующих задачах и стеке, если нет прямого исключения/переопределения. Общее ERP не подтверждает 1С:ERP; выбор куратора для адаптации отметить в changes/checks. Версия 3.11: профессиональный проект с задачами и стеком показывать в «Опыте работы», не в дополнительной информации. При неизвестном работодателе текущий проект идёт первым проектным блоком раздела, без выдуманной компании/дат/стажа; вопрос о привязке только в checks/questions. Не переносить контекст или метрики под случайного работодателя.

- Сообщения генерации и кнопка остановки показываются только выбранному владельцу studentId, включая запуск, поздние ответы, ошибки и завершение. Переключение ученика не меняет владельца задания. Глобальное ограничение одной генерации сохраняется.

- Импорт учеников: Google Drive/Sheets через DriveClient и подключение Codex app-server без model turn. Таблица фиксирована в drive-import.mjs, gid=0. Не писать в исходную таблицу. Трёхстороннее слияние с driveImport.values: заполнять пустые поля, обновлять нетронутые импортированные, ручные расхождения показывать в анкете с before/value. Пустой источник не стирает данные. Дубли сопоставлять по нормализованному Telegram/сохранённой отметке времени/ссылке PDF; неоднозначность блокирует импорт. Сохранять result/legend/resumeReady/Notion. Метаданные driveImport исключены из inputSignature и промпта. Импорт сохранять через общую saveQueue по актуальному state с резервной копией; не выполнять whole-array POST.

- Версия 3.12: в итоговом резюме/легенде исключить «Начинающий разработчик 1С», Junior, «Учебный проект» и заявления об отсутствии опыта. - Версия 3.13: targetExperienceYears — отдельное необязательное поле ученика во вкладке настроек, независимо от jobs. experienceSettings передаёт custom в целых месяцах либо default 48-54 (цель 51).
