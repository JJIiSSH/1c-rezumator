# Задачи и стиль резюме разработчика 1С

Обновлено 12 сентября 2026 года. Правила применены в постоянном промпте сервиса, версия 3.9. Модель генератора — gpt-5.6-sol с уровнем рассуждений high.

## Что показали исходные резюме

Повторно просмотрены извлечённые тексты 16 присланных PDF; подробнее разобраны описания опыта в R08, R10, R12 и R14 из первоначальной выборки.

- R08: доработки документов, отчётов и печатных форм, обмены с внешними системами, оптимизация запросов при проведении документов и формировании отчётов.
- R10: сопровождение типовых конфигураций, отчёты и обработки на СКД, исправление ошибок, оптимизация запросов, обновление изменённых конфигураций и инструкции.
- R12: задачи по ТЗ аналитиков, доработка синхронизации УТ–БП, загрузки данных, сопровождение интеграций с маркетплейсами, печатные формы и обновления.
- R14: расширение функционала, отчёты на СКД, обмены, интеграция с сайтом, торговое оборудование, консультации пользователей.

В выборке встречаются и подробные архитектурные описания. Это не означает, что их нужно воспроизводить в каждом резюме. Для данного сервиса выбран более краткий стиль по требованию куратора. Предмет работы сохраняется, ненужное описание реализации убирается. Ни выборка, ни вакансии не доказывают причину позиции резюме в выдаче hh.ru.

## Как теперь писать

| Перегруженная формулировка | Формулировка для резюме |
| --- | --- |
| Доработка заказов | Доработка оформления заказов покупателей |
| Доработка цен | Настройка расчёта цен и скидок |
| Доработка остатков | Доработка контроля складских остатков |
| Исключение запросов в цикле при проверке загружаемых записей | Оптимизация запросов и загрузки данных |
| Реализация очереди входящих сообщений в регистре сведений | Доработка обмена данными и обработки ошибок загрузки |
| Порционное чтение CSV с пакетной записью прикладных объектов | Разработка загрузки прайс-листов поставщиков в УТ |
| Приём UDP и разбор бинарных пакетов выполняются внешним шлюзом | Удалить. Это описание чужой части системы, а не задача разработчика 1С |
| Интеграция с внешним шлюзом телеметрии с проверкой идентификаторов и времени | Интеграция 1С с системой мониторинга транспорта — только если такая задача осмысленна для проекта; иначе исключить кейс |

Примеры — варианты редакторской адаптации, а не подтверждённые сведения о каком-либо ученике.

Рабочие категории: доработка конфигураций; отчёты, обработки и печатные формы; обмены и интеграции; загрузка и перенос данных; оптимизация; обновление и исправление ошибок; работа с пользователями и аналитиками.

Для конкретного работодателя выбирается несколько подходящих задач, а не весь каталог. Названия систем, документы, отчёты и предмет обмена делают описание содержательным. СКД, расширения и HTTP-сервисы уместны, когда помогают раскрыть опыт; перечислять механизм каждого шага не требуется.

## Что изменено в генераторе

Добавлены 15 паттернов по примерам куратора: ускорение отчётов; правила обмена с сопоставлением и контролем дублей; REST API интернет-магазина; управленческая отчётность; снижение обращений в поддержку; перенос доработок в расширения; маркетплейсы; Контур.Диадок; обновление конфигурации; ролевая модель; обследование и ТЗ; документация; рефакторинг; сопровождение базы; обмен через RabbitMQ при уместном контексте.

Каталог задаёт смысл, а не фиксированные формулировки. Например, ускорение отчёта по остаткам может стать ускорением отчёта по взаиморасчётам, если это подходит проекту и куратор не задал конкретный отчёт. Для торговли отдельно выделены маркетплейсы: заказы, остатки и статусы. Нужные API, брокеры и контроль дублей можно называть без описания внутреннего устройства системы.

В интерфейсе теперь 16 вариантов метрик: к прежним десяти добавлены ускорение отчёта в разах, время подготовки управленческой отчётности, снижение обращений, количество перенесённых в расширения доработок, подразделений с разграничением доступа и маркетплейсов. Остальные паттерны не обязаны содержать числа. Примеры не отменяют режим галки и приоритет введённых значений.

- Перенос каждой исходной задачи больше не обязателен: нерелевантные темы исключаются.
- Наличие механизма реализации в каждом пункте больше не требуется.
- Переписаны примеры адаптации файлов, API, очередей и оптимизации; убран образец публичного описания UDP-шлюза.
- Добавлены типичные задачи по торговле, бухгалтерии, ERP, документообороту и транспорту.
- Предложенные задачи и изменения остаются в служебных `changes/checks`; модель не выдаёт их за выдержки исходной анкеты.
- Компании, даты, образование и сертификаты не создаются из предположений. По согласованию с куратором допускаются предложенные метрики для черновика: каждая цифра помечается в changes, а проверка метрик получает clarify.

Постоянные правила: [prompt_1c_instruction.md](prompt_1c_instruction.md). Задание ученика: [prompt_1c_task.md](prompt_1c_task.md). Новая генерация читает правила с диска; старые сохранённые результаты автоматически не переписываются.

Ориентир куратора по глубине: «Доработка резервирования товаров и складских операций в 1С:Управление торговлей 11.5». Нужен понятный процесс; подробное устройство алгоритма не требуется. Формулировки выбираются по смыслу, а не механической заменой слов.

Метрики теперь управляются отдельной галкой и списком во вкладке «Настройки». При выключении показатели не добавляются. Пустой список включает автоподбор, частичный список дополняется, полный используется без новых метрик. Заданные значения куратора приоритетнее цифр исходной анкеты; повторно выбирать между ними не требуется.

С версии 3.3 в результате раскрываются два места работы: выбор куратора, иначе два последних. Это ограничение текста резюме, полная история хранится в анкете. При нехватке исходных работодателей второе место не создаётся из предположений. Разбор новой инструкции и пока не применённые предложения находятся в resume_rules_review.md.

С версии 3.4 согласован смешанный стиль: примерно половина пунктов краткие, половина раскрывает механизм, контекст и результат. Каждая работа содержит краткий контекст и завершается строкой стека без минимального количества технологий. Это актуализирует прежнее пожелание краткости: внутренняя структура алгоритмов по-прежнему не нужна. Достраивание задач и метрик сохраняется, режим метрик важнее пропорции 50/50. Гражданство и контакты берутся из анкеты/исходного резюме, Москва остаётся фиксированной.

С версии 3.5 прежний запрет на предложение образования заменён отдельным правилом куратора: допустим предложенный вуз/направление для черновика при сохранении исходных данных и обязательной пометке замены в changes/checks. Это не распространяется на сертификаты, номера дипломов, научные степени и выдуманные даты. Легенда 1.1 сохраняет происхождение такой замены.

## Распространённые конфигурации, версия 3.8

Обязательна одна из БП, УТ, ERP, КА, УНФ, Розницы или Документооборота: задача и стек той же работы. Самописные решения сохраняются при уместности, но одних их недостаточно. ЗУП исключена по решению куратора. Версии подбираются по периоду; предложенные детали отмечаются в changes/checks.

Источники для рабочего набора, проверены 12 сентября 2026: [официальный каталог 1С](https://v8.1c.ru/vse-programmy-1c/), [решения 1С для торговли](https://torg.1c.ru/). Каталог подтверждает назначение продуктов, а не сравнительные доли рынка; список не является количественным рейтингом.

## Целевой стаж, версия 3.9

По решению куратора 4-4,5 года суммарно на две работы (48-54 месяца). Предложенные периоды существующих работодателей можно корректировать; оригинальную хронологию сохранять в источниках, изменения отмечать в changes/checks. Это позиционирование черновика, а не критерий Senior: уровень не определяется одной длительностью.
